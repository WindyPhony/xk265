# Audit of Task 03: H.265 algorithm → xk265 RTL traceability

Audited source: [H265_ALGORITHM_RTL_TRACEABILITY.md](H265_ALGORITHM_RTL_TRACEABILITY.md). This is a correction of its **forward matrix**, not a claim of HEVC conformance. `CONFIRMED_RTL` means the stated, narrow behavior is visible in RTL; it does not establish full standard support. `IMPLIED_BY_CONNECTIVITY` means port wiring is visible but the complete data choice or operation was not proved. `INFERRED` means a plausible interpretation remains unproved. `UNKNOWN` means no sufficient implementation trace. `CONFIRMED_TESTBENCH` applies only to testbench setup. No simulator experiment is used as proof in this audit.

## Strong mappings

| Prior IDs | Why the **narrowed** mapping is strong |
| --- | --- |
| A2 | `enc_ctrl` produces stage-specific CTU coordinates from counts and stage completion ([RTL](rtl/top/enc_ctrl.v#L145)). |
| A3, B6 | POSI and IME compare costs and emit partition fields; POSI also retains a winning mode. `enc_data_pipeline` only forwards/delays those fields ([POSI](rtl/posi/posi_partition_decision.v#L809), [IME](rtl/ime/ime_partition_decision.v#L873), [pipeline](rtl/top/enc_data_pipeline.v#L84)). |
| B1–B5 | PREI proposes modes from current samples; POSI and REC have separate reference/prediction paths. `intra_pred` branches on mode 0/1 and has angular parameters/index arithmetic ([PREI](rtl/prei/md_top.v#L127), [POSI](rtl/posi/posi_prediction.v#L263), [REC](rtl/rec/rec_intra/intra_pred.v#L215)). `dc_planar` in PREI proposes **mode IDs**; it is not the planar/DC pixel predictor ([RTL](rtl/prei/DC_Plannar.v#L80)). |
| C2–C5 | IME address logic emits candidate MV/addresses; `ime_sad_array` computes absolute pixel differences; `ime_cost_store` adds MV cost and retains minima. FME has interpolated samples, SATD/cost comparison and chosen fractional MV ([IME abs](rtl/ime/ime_sad_array.v#L7126), [store](rtl/ime/ime_cost_store.v#L1568), [FME](rtl/fme/fme_top.v#L465)). |
| D1–D2 | `rec_top` compares aggregate I/P costs in one CTU-level `type_r` register; POSI's QP→lambda table, rate estimate and distortion-plus-rate addition are explicit ([REC](rtl/rec/rec_top.v#L327), [rate](rtl/posi/posi_rate_estimation.v#L84), [sum](rtl/posi/posi_satd_cost.v#L484)). |
| E1, E2b, F2a–F2b, G1–G3 | REC subtracts prediction from source; TQ routes size-controlled forward/inverse transform and quantizer results; reconstruction adds or bypasses residual, clips and stores pixels ([sub](rtl/rec/rec_wrapper/rec_buf_wrapper.v#L742), [TQ](rtl/rec/rec_tq/tq_top.v#L623), [add/clip](rtl/rec/rec_wrapper/rec_buf_wrapper.v#L1243)). |
| H1–H3b | `db_bs` makes TU/PU edge flags; `db_filter` computes boundary strength and selects luma/chroma filter engines. SAO statistics, offset cost comparison, and application are separately wired ([BS](rtl/db/db_filter.v#L135), [filters](rtl/db/db_filter.v#L344), [SAO decision](rtl/db/sao_type_decision.v#L161), [SAO top](rtl/db/sao_top.v#L175)). |
| I1–I4b | CABAC syntax buses feed binarization/sorting, context lookup/update, range and low arithmetic. Context helpers contain explicit MPS/LPS state transitions ([top](rtl/cabac/cabac_top.v#L406), [context](rtl/cabac/cabac_ucontext_tt.v#L59), [low](rtl/cabac/cabac_ulow.v#L131)). |
| J1a | `bs_val_i` increments one counter per emitted **byte**; the counter output feeds rate control ([counter](rtl/top/enc_data_pipeline.v#L243), [byte output](rtl/cabac/cabac_top.v#L842)). |

## Weak mappings

| Prior IDs | Missing proof / corrected level |
| --- | --- |
| A1 | `enc_ctrl` schedules a picture request and CTUs, but frame-sequence control/DPB ownership is outside this RTL trace. `h265enc_top` is a wiring parent, not another frame processor. `CONFIRMED_RTL` only for scheduling; frame processing as a whole `UNKNOWN`. |
| A4–A5, E2a | Partition bits and TQ sizes are present, but `mc_ctrl` only sequences chroma/TQ work; it is not a PU partition selector. `tq_top` accepts `tq_size_i`; it does not prove autonomous TU-tree/transform-type choice. `IMPLIED_BY_CONNECTIVITY` for end-to-end PU/TU traversal ([MC](rtl/rec/rec_mc/mc_top.v#L311), [TQ](rtl/rec/rec_tq/tq_top.v#L628)). |
| B7 | REC has two `intra_pred` instances and U/V control, but the original row did not prove every chroma mode and output selection. Narrow to U/V prediction path; full chroma-mode support `UNKNOWN` ([REC](rtl/rec/rec_intra/intra_top.v#L312)). |
| C1 | Fetch reads reference samples and feeds IME/FME/MC; whether stored filtered output becomes a later reference is outside the shown RTL interface. `CONFIRMED_RTL` for access, `UNKNOWN` for autonomous DPB. |
| C6–C7 | Spatial A0/A1/B0/B1/B2 neighbor presence and simplified skip test exist. No complete HEVC merge-list construction, deduplication or temporal candidate was proved. Skip MV and its coded-length term are tied to constants in the inspected path ([candidate](rtl/fme/fme_mv_candidate_prepare.v#L239), [skip](rtl/fme/fme_skip.v#L724)). |
| H4 | SAO application and fetch/store port wiring are visible. The exact filtered pixel lane through `dbsao_datapath` and external-memory return as next-picture reference were not followed; full loop `IMPLIED_BY_CONNECTIVITY`/`UNKNOWN` ([DB/SAO](rtl/db/dbsao_top.v#L344), [fetch](rtl/fetch/fetch_top.v#L574)). |
| I5 | `cabac_bitpack` emits bytes and `cabac_ulow` has an end flush. A standards-specific terminate-bin operation was not isolated. Byte packing `CONFIRMED_RTL`; termination `UNKNOWN` ([low](rtl/cabac/cabac_ulow.v#L316), [pack](rtl/cabac/cabac_top.v#L842)). |
| J1 | The RC arithmetic exists, but the supplied testbench disables CTU RC (`sys_rc_lcu_en=0`) and `rate_control` then uses initial QP. Its feedback counter counts bytes despite the `bitnum` name. Runtime RC in this testbench is **not** demonstrated ([RTL](rtl/prei/rate_control.v#L205), [testbench](sim/top_testbench/tb_enc_top.v#L998)). |
| K1–K2 | FME spatial MV memory and DB boundary MV memory have distinct consumers. Intra pixel neighbors and PREI/POSI **mode** RAMs are different data, not one neighbor-sample store. Narrow each mapping accordingly. |

## Incorrect mappings

| Prior ID/claim | Correction |
| --- | --- |
| D1: `IinP_flag_gen` performs I/P cost choice | Remove it from chooser. `rec_top` performs the comparison; `IinP_flag_gen` forms flags used by later blocks ([REC](rtl/rec/rec_top.v#L327)). |
| A3: `enc_data_pipeline` chooses CU depth | It transports partition data; POSI/IME decision blocks choose fields ([pipeline](rtl/top/enc_data_pipeline.v#L84)). |
| A4: `mc_ctrl` selects PU partitions | It launches chroma and TQ phases; `mc_tq` consumes `fmeif_partition_i` to fetch stored prediction ([MC](rtl/rec/rec_mc/mc_top.v#L311)). |
| C2: search is a *fixed configuration* | IME search is programmed by command fields. The provided testbench loads command records; no named full/diamond/hex search can be assigned ([control](rtl/ime/ime_ctrl.v#L189), [testbench](sim/top_testbench/tb_enc_top.v#L670)). |
| C7: arbitrary merge candidate MV/bit-length evaluated | In the examined skip-cost path `skip_fmv_x/y=0` and `bitrate=5`; candidate-valid/skip-index logic remains. Do not equate it to full merge-mode evaluation ([RTL](rtl/fme/fme_skip.v#L724)). |
| C8: `mc_top` generates all Y/U/V predictions from reference pixels | Luma prediction is read from the **FME prediction buffer** through `mc_tq`; `mc_chroma_top` fetches/interpolates chroma ([MC](rtl/rec/rec_mc/mc_top.v#L275), [buffer read](rtl/rec/rec_mc/mc_tq.v#L433), [FME pred](rtl/fme/fme_top.v#L703)). |
| F1: QP is fixed in RTL | RTL has conditional feedback, ROI and clipping; the **testbench** disables CTU RC. These are different evidence sources ([RTL](rtl/prei/rate_control.v#L205), [testbench](sim/top_testbench/tb_enc_top.v#L646)). |
| H1: `db_bs` calculates final BS | It marks edges; `db_filter` computes `bs_w` using edge, CBF, MV differences and enable ([RTL](rtl/db/db_filter.v#L135)). |
| K2: PREI/POSI mode RAMs hold intra reference pixels | They hold mode records. Reconstructed neighboring pixels use `intra_ref`/buffer paths ([REC](rtl/rec/rec_intra/intra_top.v#L235), [mode connection](rtl/top/enc_core.v#L549)). |
| Original reconstruction table: SAO→external store marked `CONFIRMED_RTL` end-to-end | Only stage ports were shown; downgrade full arrow to `IMPLIED_BY_CONNECTIVITY`. External store→next reference remains `UNKNOWN` in RTL. |

The original parent rows E2, F2, H2, H3, I3 and I4 duplicate their more precise child rows E2a/b, F2a/b, H2a/b, H3a/b, I3a/b and I4a/b. The corrected matrix uses the child rows only; the parent IDs are **replaced, not additional functions**. The original J1a is retained separately from J1 because counting and QP control are distinct.
