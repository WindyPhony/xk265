# DB/SAO — Deblocking Filter + Sample Adaptive Offset

## 1. Overview

The DB/SAO subsystem performs in-loop deblocking filtering and sample adaptive offset on reconstructed CTU pixels before they are written back to the DPB and used as references for subsequent CTUs. It operates as pipeline stage 4 in the xk265 encoder pipeline.

**Key Parameters** (from `enc_defines.v`):
- `PIXEL_WIDTH`: 8 bits
- `FMV_WIDTH`: 10 (motion vector component width)
- `SAO_OPEN`: 0 (SAO may be conditionally compiled out)
- `DATA_WIDTH`: 256 (8 pixels × 32 bits packed per side)

**Total processing per CTU**: ~1,439 cycles (LOAD 128 + DBY 263 + DBU 71 + DBV 71 + SAO 451 + OUT 455)

## 3. Controller FSM

**RTL**: `rtl/db/dbsao_controller.v`

The controller is a 7-state FSM with a 9-bit cycle counter (`cnt_o`).

### 3.1 State Encoding

| State | Encoding | Duration (cycles) | Description |
|-------|----------|-------------------|-------------|
| IDLE  | 3'b000   | 1                 | Waiting for `sys_start_i` |
| LOAD  | 3'b001   | 128               | Load top/left/TL pixels from previous CTU |
| DBY   | 3'b011   | 263               | Deblocking filter — luma (16×16 4×4 blocks) |
| DBU   | 3'b010   | 71                | Deblocking filter — chroma U (8×8 4×4 blocks) |
| DBV   | 3'b110   | 71                | Deblocking filter — chroma V (8×8 4×4 blocks) |
| SAO   | 3'b100   | 451               | Sample adaptive offset statistics + offset calculation |
| OUT   | 3'b101   | 455               | Write filtered pixels back to RAM and fetch |

### 3.2 State Transitions

```
IDLE → [start_i] → LOAD → [cnt=128] → DBY → [cnt=263] → DBU → [cnt=71] → DBV → [cnt=71] → SAO → [cnt=451] → OUT → [cnt=455] → IDLE
```

### 3.3 Handshake

- `sys_start_i` pulse triggers transition from IDLE to LOAD
- `sys_done_o` asserted when `next_state == IDLE` (OUT→IDLE transition)

## 4. Datapath (`dbsao_datapath`)

**RTL**: `rtl/db/dbsao_datapath.v`

### 4.1 Line Buffers

The datapath maintains line buffers to hold pixels from the previous CTU row and left column:

| Buffer | Width | Depth | Description |
|--------|-------|-------|-------------|
| `top_y_r[15:0]` | 128 bits | 16 entries | Top luma line buffer (16 × 4 pixels × 8 bits) |
| `top_u_r[7:0]` | 128 bits | 8 entries | Top chroma U line buffer |
| `top_v_r[7:0]` | 128 bits | 8 entries | Top chroma V line buffer |
| `left_y_r[15:0]` | 128 bits | 16 entries | Left luma line buffer |
| `left_u_r[7:0]` | 128 bits | 8 entries | Left chroma U line buffer |
| `left_v_r[7:0]` | 128 bits | 8 entries | Left chroma V line buffer |
| `y_tl_r` | 128 bits | 1 entry | Top-left luma block |
| `u_tl_r` | 128 bits | 1 entry | Top-left chroma U block |
| `v_tl_r` | 128 bits | 1 entry | Top-left chroma V block |

### 4.2 Filtered Block Storage

| Buffer | Width | Depth | Description |
|--------|-------|-------|-------------|
| `block[7:0]` | 128 bits | 8 entries | Filtered 4×4 block storage for output reordering |
| `right_block_0` | 128 bits | 1 entry | Rightmost column block 0 |
| `right_block_1` | 128 bits | 1 entry | Rightmost column block 1 |

### 4.3 Pixel Loading (LOAD State, 128 cycles)

During LOAD, top-line pixels from the previous CTU row are read via `top_ren_o`:
- `cnt_i[6:2]` selects the 4×4 block within the CTU (luma: blocks 0–15, chroma: blocks 16–23 for U, 24–31 for V)
- `cnt_i[1:0]` selects the 32-bit pixel group within the 128-bit block
- Each read loads 4 pixels (32 bits) into the appropriate position of the 128-bit line buffer

### 4.4 P/Q Block Preparation (DBY/DBU/DBV States)

During deblocking states, the datapath prepares P-side and Q-side 128-bit blocks for `db_filter`:

- **P-side** (`dbf_p_o`): 4 rows of 4 pixels from the block to the left/top of the boundary
- **Q-side** (`dbf_q_o`): 4 rows of 4 pixels from the block to the right/bottom of the boundary

The block source is selected from:
- `blk_l_0`, `blk_l_1` — left column or top row blocks (from line buffers)
- `blk_r_0`, `blk_r_1` — current CTU blocks (from `rec_pxl_i_w`)
- `block[0–7]` — previously filtered blocks (feedback path)

### 4.5 Vertical/Horizontal Edge Handling

- `is_ver_o = !cnt_d2[1]` — vertical edge when bit 1 of delayed counter is 0
- Vertical edges filter across columns; horizontal edges filter across rows
- P/Q block sources differ based on edge orientation

### 4.6 IinP Flag Propagation

The `IinP_flag_o` signal indicates whether the current filter boundary involves an intra-coded block:
- Top boundary: uses `IinP_flag_i[2]` (top) and `IinP_flag_i[0]` (current)
- Left boundary: uses `IinP_flag_i[1]` (left) and `IinP_flag_i[0]` (current)
- Internal boundaries: uses `IinP_flag_i[0]` only

## 5. Boundary Strength (`db_bs`)

**RTL**: `rtl/db/db_bs.v`

### 5.1 Edge Detection

The module detects TU and PU boundaries within the CTU:

- **TU edges**: Computed from `mb_partition_i[20:0]` (CU split flags). Produces 16 vertical edges (`v0–v15`) and 7 horizontal edges (`h1–h7`) for luma; fewer for chroma.
- **PU edges**: Computed from `mb_p_pu_mode_i[41:0]` (inter PU partition modes).

### 5.2 Boundary Strength Logic

The BS computation (in `db_filter.v`) is:

```
if (sys_db_ena_i == 0)       → BS = 0 (no filter)
if (edge_type == INTRA)      → BS = tu_edge (binary: 0 or 1)
if (edge_type == INTER)      → BS = is_luma AND (
                                   (tu_edge AND (cbf_p OR cbf_q)) OR
                                   (pu_edge AND (|mv_diff| > 3))
                               )
chroma inter                  → BS = 0 (no filtering)
```

### 5.3 MV Comparison

- MV components: `mv_p_i[19:10]` (x), `mv_p_i[9:0]` (y), each 10-bit signed
- Absolute difference computed for x and y separately
- BS is set if either x or y difference exceeds 3

### 5.4 Top-Line Buffers for BS

The BS module uses three RAM-based line buffers to store QP, CBF, and TU/PU partition info from the previous CTU row:

| RAM | Width | Depth | Description |
|-----|-------|-------|-------------|
| `db_tupu_ram_sp_64x32` | 32 bits | 64 entries | TU/PU partition info |
| `db_cbf_ram_sp_64x16` | 16 bits | 64 entries | CBF (Y/U/V) info |
| `db_qp_ram_sp_64x20` | 20 bits | 64 entries | QP info |

## 6. Deblocking Filter (`db_filter`)

**RTL**: `rtl/db/db_filter.v`

### 6.1 Pixel Data Format

Input P/Q blocks are 128 bits each, organized as 4 rows of 4 pixels:

**Vertical edge** (is_ver = 1):
```
P: [p0_3|p0_2|p0_1|p0_0] [p1_3|p1_2|p1_1|p1_0] [p2_3|p2_2|p2_1|p2_0] [p3_3|p3_2|p3_1|p3_0]
Q: [q0_0|q0_1|q0_2|q0_3] [q1_0|q1_1|q1_2|q1_3] [q2_0|q2_1|q2_2|q2_3] [q3_0|q3_1|q3_2|q3_3]
```

**Horizontal edge** (is_ver = 0):
```
P: [p0_3|p1_3|p2_3|p3_3] [p0_2|p1_2|p2_2|p3_2] [p0_1|p1_1|p2_1|p3_1] [p0_0|p1_0|p2_0|p3_0]
Q: [q0_0|q1_0|q2_0|q3_0] [q0_1|q1_1|q2_1|q3_1] [q0_2|q1_2|q2_2|q3_2] [q0_3|q1_3|q2_3|q3_3]
```

### 6.2 QP Computation

```
qpw   = (qp_p + qp_q + 1) >> 1          // average QP
qp_lc = is_luma ? qpw : qpc             // luma uses qpw, chroma uses qpc
qpc   = clip3(qpw - 6, qpw, mapped_qpw) // chroma QP mapping (HEVC Table 8-15)
```

### 6.3 Threshold Computation

- **Beta** (`db_lut_beta`): 7-bit output from 6-bit QP address, range 16–43
- **tC** (`db_lut_tc`): 5-bit output from (qp_lc, INTRA_flag) address, range 18–50
- INTRA adds +2 to tC address (coarser filter for intra boundaries)

### 6.4 Filter Decision Logic

```
d          = dp + dq                                          (activity metric)
d_less_beta = (d < beta)                                      (filter enable)
bs_w       = {0, INTRA? tu_edge : luma && (tu_edge && cbf || pu_edge && mv_diff>3)}
edge_type  = (mb_type == INTRA || IinP_flag == 1) ? INTRA : INTER
```

**Strong vs Normal selection**:
```
dsam0 = (dqp0*2 < beta>>2) && (dp0_3_0 + dq0_3_0 < beta>>3) && (dpq0_0_0 < tc*3/2)
dsam3 = (dqp3*2 < beta>>2) && (dp3_3_0 + dq3_3_0 < beta>>3) && (dpq3_0_0 < tc*3/2)
norm_str = dsam0 && dsam3                                      (both ends qualify → strong)
```

**Filter count** (normal filter):
```
filter_cout_p = (dp < beta_m) ? 2 pixels : 1 pixel
filter_cout_q = (dq < beta_m) ? 2 pixels : 1 pixel
```

### 6.5 Filter Output MUX

Priority order:
1. **Chroma INTRA**: `db_chroma_filter` output (p0 only, 1 pixel filtered per side)
2. **No filter**: Pass-through (bs=0 or d ≥ beta or !not_nature_edge)
3. **Strong**: `db_strong_filter` output (p0, p1, p2 — 3 pixels filtered per side)
4. **Normal**: `db_normal_filter` output (1 or 2 pixels filtered per side, selected by filter_cout)

Output repacked based on `is_ver`:
```
p_o = is_ver ? {p0_3,p0_2,p0_1,p0_0, p1_3,..., p3_3,...} : {p0_3,p1_3,..., p3_0,...}
q_o = is_ver ? {q0_0,q0_1,q0_2,q0_3, q1_0,..., q3_3,...} : {q0_0,q1_0,..., q3_3,...}
```

### 6.6 Strong Filter (`db_strong_filter`)

- Inputs: 32 pixels (4×4 P + 4×4 Q) + tc (5-bit)
- Outputs: 24 pixels (3 filtered per side × 4 rows × 2 sides)
- Uses clip operations with `tc*2` and `tc` thresholds
- 3-stage pipeline: tc computation → pixel difference computation → clip + output

### 6.7 Normal Filter (`db_normal_filter`)

- Inputs: 32 pixels + tc (5-bit)
- Outputs: up to 16 pixels (2 filtered per side × 4 rows × 2 sides)
- Uses `not_nature_edge` flag per row (4-bit) to selectively skip rows
- Delta computation: `delta = clip3(-tc, tc, (((q0 - p0) << 2) + p1 - q1 + 4) >> 3)`

### 6.8 Chroma Filter (`db_chroma_filter`)

- Inputs: 16 pixels (2 columns × 4 rows × 2 sides) + tc
- Outputs: 8 pixels (1 filtered per side × 4 rows × 2 sides)
- Only filters p0/q0 (nearest pixels to boundary)
- Only active for INTRA chroma edges

## 7. MV Buffer (`db_mv`)

**RTL**: `rtl/db/db_mv.v`

The MV buffer reads motion vector data from the FME MV RAM for boundary strength computation:

| RAM | Width | Depth | Description |
|-----|-------|-------|-------------|
| `db_mv_ram_sp_64x20` | 20 bits | 64 entries | Current CU MV storage |
| `db_mv_ram_sp_512x20` | 20 bits | 512 entries | Top MV buffer (previous CTU row) |

- MV data: 20 bits = {mv_x[19:10], mv_y[9:0]}, each component 10-bit signed
- Read during DBY state via `mb_mv_ren_o` / `mb_mv_raddr_o` (6-bit address)

## 8. SAO (`sao_top`)

**RTL**: `rtl/db/sao_top.v`

### 8.1 SAO Modes

The SAO module supports two offset types:
- **EO (Edge Offset)**: 4 directions (0°, 45°, 90°, 135°) — classifies pixels by edge pattern
- **BO (Band Offset)**: 32 bands — classifies pixels by intensity band

### 8.2 SAO Processing

1. **Statistics collection** (`sao_statistic`): Accumulates per-direction EO stats and per-band BO stats
2. **Band offset pre-decision** (`sao_bo_predecision`): Pre-selects BO candidates
3. **Offset calculation** (`sao_cal_offset`): Computes optimal offset per type
4. **Type decision** (`sao_type_decision`): Selects best SAO mode (EO0/EO1/EO2/EO3/BO/none)
5. **Offset application** (`sao_add_offset`): Applies selected offset to reconstructed pixels

### 8.3 SAO Input/Output

**Inputs**:
- `rec_line_i_0` through `rec_line_i_5`: 6 lines of 48 bits (6 pixels × 8 bits) — reconstructed pixels
- `ori_line_i_0` through `ori_line_i_3`: 4 lines of 32 bits (4 pixels × 8 bits) — original pixels (for statistics)
- `sao_4x4_x_i`, `sao_4x4_y_i`: 4-bit coordinates of current 4×4 block
- `bo_predecision`: 15-bit BO pre-decision from `sao_bo_predecision`

**Outputs**:
- `sao_block_o`: 128 bits (16 × 8) — offset-applied pixels
- `sao_data_o`: 62 bits — SAO parameters for CABAC coding

### 8.4 SAO Data Output to CABAC

The 62-bit `sao_data_o` contains:
- SAO merge flag
- SAO type index (EO0/EO1/EO2/EO3/BO)
- Band offset class/offsets
- Edge offset class/direction/offsets

## 9. Memory Architecture

### 9.1 External Memory Interface

The datapath reads/writes reconstructed pixels via the external memory interface:

**Read ports** (to fetch):
- `rec_ren_o`: Read enable
- `rec_4x4_x_o[3:0]`, `rec_4x4_y_o[3:0]`: 4×4 block coordinates
- `rec_4x4_idx_o[4:0]`: Line index within 4×4 block
- `rec_sel_o[1:0]`: Y/U/V selection (00=Y, 10=U, 11=V)
- `rec_siz_o[1:0]`: Block size (SIZE_08 = 8×4)

**Write ports** (to fetch):
- `fetch_wen_o`: Write enable
- `fetch_w4x4_x_o[4:0]`, `fetch_w4x4_y_o[4:0]`: Coordinates
- `fetch_wsel_o[1:0]`: Y/U/V selection
- `fetch_wdata_o[127:0]`: 16 pixels (128 bits)
- `fetch_wprevious_o`: Write to previous CTU buffer

### 9.2 Internal RAM-Based Buffers

| Module | Width | Depth | Purpose |
|--------|-------|-------|---------|
| `db_mv_ram_sp_64x20` | 20 | 64 | Current CU MV storage |
| `db_mv_ram_sp_512x20` | 20 | 512 | Top MV buffer |
| `db_tupu_ram_sp_64x32` | 32 | 64 | TU/PU partition info |
| `db_cbf_ram_sp_64x16` | 16 | 64 | CBF info |
| `db_qp_ram_sp_64x20` | 20 | 64 | QP info |

All RAMs are single-port, synchronous read, inferred behavioral RAM.

## 10. Control Architecture

### 10.1 Pipeline Integration

- `sys_start_i` pulse from `enc_ctrl` triggers processing
- `sys_done_o` returned to `enc_ctrl` when OUT state completes
- DB reads MV data from FME MV RAM (shared resource, no arbitration needed since FME is done)
- DB reads/writes reconstructed pixels via fetch memory interface

## 12. Outstanding Questions

1. **SAO_OPEN define**: `SAO_OPEN` is set to 0 in `enc_defines.v`. This may gate SAO logic at synthesis. The RTL always instantiates `sao_top`, but `sys_sao_ena_i` may disable it at runtime.
2. **SAO line buffer depth**: Exact number of SAO lines buffered in `dbsao_datapath` is unclear from partial file reads. The 6 rec lines and 4 ori lines suggest 4×4 block granularity.
3. **BS module internal RAMs**: The exact read/write addressing scheme for the TU/PU, CBF, and QP top-line RAMs requires further analysis of the truncated `db_bs.v` file.
4. **Chroma filter conditions**: The chroma filter only activates for INTRA edges (`flt_chroma_flag = !is_luma && bs!=0 && edge_type==INTRA`). Inter chroma is never filtered.
5. **not_nature_edge**: The `not_nature_edge` output from `db_normal_filter` (4-bit, one per row) controls per-row filter skip. The exact condition requires reading the complete `db_normal_filter.v`.
